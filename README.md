## 它解决什么问题

**问题**：想找一起上课的人（课搭子、同路人），现在只能把两份课表摊开来人肉比对——
「你周三下午在哪？」「我在东 6 三楼。」来回问半天，还经常漏掉。

**做法**：把教务系统导出的 `.ics` 课表丢进浏览器，建一个群，同学凭邀请码/二维码进来。
群组页直接给每个人算好**和你重合的课时数**，并按「同教室 / 同楼栋 / 同区域 / 不同区域」分级；
点开某人还能看两张课表叠在一起的网格图，一键导出 PNG。

**现在的形态**：它**已经部署在服务器上对外服务**——反向代理提供 HTTPS，站点挂在子路径下
（形如 `https://<主机>/tongge/`），容器只监听本机端口，不直接对外。本地也照样能跑：
`node server.js`，浏览器打开 `http://localhost:3000` 就能用。

它仍然**不做陌生人匹配**：进群靠邀请码，可见范围限于同群成员。

## 核心功能

| 功能 | 说明 |
|---|---|
| 课表解析 | 支持 `.ics` / `.txt`，**在浏览器里解析**，只把结构化结果发给服务器 |
| 导出教程 | 首页有「第一次用？看看怎么导出 .ics」，以 Elychron / Celechron 设置页为例，带截图 |
| 建群 / 入群 | 8 位邀请码 + 二维码；扫码或输码即可，不用加好友 |
| 邀请链接 | 可同时发多条，每条各设有效期（1 天 / 3 天 / 7 天 / 1 个月 / 永久），可单独作废 |
| 重合统计 | 按同教室 / 同楼栋 / 同区域 / 不同区域分类，按周切换 |
| 双人网格图 | 一个格子同时表达「地点关系」和「这是谁的课」，可导出 PNG（全学期视图） |
| 备注 | 给群里的人起一个只有你自己看得见的备注名（像微信备注名） |
| 本地比对 | 首页「本地快速比对」选两份文件直接在浏览器里比对，不发给服务器 |
| 群管理 | 改名、移除成员、审批进群申请、换群码、邀请链接管理 |
| 深色模式 | 默认跟随系统，可手动指定并记住；导出图片跟随当前主题 |
| 账号 | 注册 / 登录 / 改密码 / 注销；密码 scrypt 加盐哈希，不存明文 |
| 注册验证码 | 一道 2–4 步的个位数四则运算，**服务端画成 PNG** 发下来；答案只活在内存里，3 分钟过期、用过即废 |
| 管理员 | 全量账号 / 群组 / 审计日志视图，命令行授权管理员 |

## 快速开始

### 部署到服务器（正式服的跑法）

**前提**：服务器上装了 Docker，并且有一个反向代理（Nginx / Caddy / 1Panel 等）
负责 HTTPS 与子路径。

**第 0 步：配好根密钥**——它是存储加密的唯一钥匙，**必须放在部署目录之外**
（放在 `/opt/tongge` 里就等于和数据一起被拷走，加密白做）：

```bash
# 服务器上一般没装 node（应用跑在容器里），所以用容器生成一把
KEY=$(docker run --rm node:22-alpine node -e "console.log(require('crypto').randomBytes(32).toString('hex'))")
sudo install -d -m 700 /etc/tongge
printf 'TONGGE_ROOT_KEY=%s\n' "$KEY" | sudo tee /etc/tongge/key.env >/dev/null
sudo chmod 600 /etc/tongge/key.env
```

**第 1 步：起服务**

```bash
docker compose up -d --build     # 构建 + 启动
docker compose logs -f tongge    # 看启动横幅
docker compose down              # 停服务（数据在卷里，不会丢）
```

> 没有根密钥，服务会**拒绝启动**，并打印上面那条生成命令——这是故意的：
> 绝不允许悄悄退化成明文存盘（那没人会发现，而启动失败一眼就看得见）。
> 从旧版本升级上来还要跑一次数据迁移，见 [部署详解](#部署详解) 的「存储加密与迁移」。

容器默认只映射到 `127.0.0.1:3560`，**由反代转发进来**，站点形如 `https://<主机>/tongge/`。
反代要做哪三件事、子路径怎么配、真实 IP 的问题，全在 [部署详解](#部署详解)。

### 本机跑起来（开发 / 预览，1 分钟）

**前提**：装了 Node.js 18 或更新（`node -v` 能打印版本号就行）。**不需要 `npm install`。**

```bash
node server.js          # 或 npm start
```

浏览器打开控制台打印的 `http://localhost:3000` 就能用；同网段的其他设备用
`http://<本机IP>:3000` 也能访问（Windows 首次运行会弹防火墙提示，选「允许访问」）。

## 怎么用

1. **注册**：昵称（全局唯一，≤10 字）+ 密码（≥6 位）。密码用 scrypt 加盐哈希存储，不存明文。

2. **上传课表**：点首页的虚线框选 `.ics` / `.txt`。
   不知道怎么导出？首页有「第一次用？看看怎么导出 .ics」。
   浏览器本地解析，**只把结构化结果发给服务器，原始文件不上传**。

3. **建群**：得到邀请码 + 二维码，发给同学。群主还可以**同时发多条邀请链接**，
   每条单独设有效期，详见 [邀请链接与有效期](#邀请链接与有效期)。

4. **看重合**：群组页每个人都直接显示与你的**重合课时数**，按同教室 / 同楼栋 / 同区域 / 不同区域分类。
   头顶可按周切换。

5. **比对**：点任一成员 → 双人网格图 → 「保存课表截图」导出 PNG。

6. **备注**：群组页每个成员行上有「备注」，给 TA 起一个只有你自己看得见的名字。
   别人看到的还是 TA 原来的昵称，导出的图也不受影响。

7. **管人**（仅群主）：
   - 群名旁边的「改名」可以随时重命名，群里所有人立刻看到
   - 每个成员行右侧有「移除」按钮，确认后把人移出群组（对方要重新输邀请码才能进来）
   - 「谁能进群」：**拿到链接就能进** 或 **要我同意**。后者会在群组页顶部出现「想进群的人」，
     逐条 同意 / 拒绝；申请人首页能看到「等群主同意」
   - 群主不能移除自己——想结束就解散群组

8. **注销账号**：首页最下方，要输一次密码确认。注销后账号、课表、备注全没了，无法恢复。
   你还是群主的话：群里还有别人 → 群主自动转给最早加入的那位；只有你自己的群 → 直接解散。

页面上的两个贴心处：群组页「上传 / 更新我的课表」下面有一行状态（还没传 / 当前几个时段 /
什么时候更新的），上传过程中变成「正在解析并上传…」，按钮同时禁用防重复点。

> **本地快速比对**：首页底部的入口选两份文件，直接在浏览器里比对，**不把课表发给服务器**。
> 入口在登录后的首页，所以还是得先有账号，但比对过程完全在本地。

## 网格怎么看

一个格子内**上半永远是「你」，下半永远是「TA」**。两种信息用两个通道表达，互不干扰：

| 通道 | 含义 |
|---|---|
| **底色** | 两人在该时段的地点关系：同教室 / 同楼栋 / 同区域 / 不同区域 / 未知；浅灰 = 只有一个人在上 |
| **边框** | 这是谁的课：**深色实线 = 你**，**白色实线 = TA** |

这样即使同一个格子里两人都在上课、底色相同，也能一眼分清哪块是自己的。

电脑上（窗口 ≥1000px）课表页会自动放宽到 1280px，7 天一次看全；
手机上仍是窄栏，课表在卡片内左右滑动，不会把整页撑宽。

## 周次怎么算

周次胶囊上写两个数字，例如 `第 3 周 · 年 40 周`：

- **第 N 周** —— 教学周，从两份课表里最早的日期那周起算。和学校通知的口径一致，
  **单双周也按它算**。
- **年 N 周** —— 这一周在自然年里的 ISO 周次（含 1 月 4 日的那周是第 1 周）。
  它只由日期决定，和课表内容无关。

**为什么两个都给**：教务导出的 `.ics` 里混着调休补课、期末考试之类的零散日期，
它们会把「最早日期」提前，教学周的编号就整体偏了；年周次不受影响，可以拿来对照。

因为同样的原因，**个别日期可能落在常规教学周之外**（比如国庆调休那周的周六有课），
课表一律按 `.ics` 里的真实日期显示，不会因为「不是教学周」就把课丢掉。页面上也有这行说明。

### 几个设计上的取舍

- **单双周不做奇偶推算**，直接按 `.ics` 里的真实日期判断。调休、临时加课、停课都天然正确。
- **屏幕按周显示，导出是全学期**。导出的图包含单周/双周两套，只有真正有差异的格子才标注
  「单周 / 双周」；两套一致的课不产生任何标注。导出与当前选中的周次无关。
- **导出会剔除只出现一次的条目**。教务导出的 `.ics` 里混着期末考试和调休补课，它们只出现一次
  却会和常规课撞格。实测：不过滤时导出图有 28 处假标注，过滤后剩 5 处真单双周。
  该过滤**只作用于导出**，屏幕上仍按真实日期原样显示。

## 邀请链接与有效期

**群是永久的，有寿命的只是邀请链接。** 两者在数据里是分开的：

| | 是什么 | 有效期 |
|---|---|---|
| `g.code` | 群的**永久地址** | 永不过期，也不该过期——群为什么要有寿命 |
| `g.invites[]` | 发给同学的**邀请链接**，可以同时存在多枚 | 每枚各自设：1 天 / 3 天 / 7 天 / 1 个月 / 永久 |

群主在群组页点「管理邀请链接」进独立的管理页，那里能：发新链接（选有效期 + 起备注名）、
看每条还剩多久、单条作废 / **勾选批量作废**、展开「已失效记录」查看并删除存档。
成员只看得到**还能用**的链接（方便帮忙拉人），管理痕迹只给群主。

几个刻意定下的行为：

- **过期或作废只挡新人**。已经在群里的人完全不受影响——成员是按 userId 记的，跟链接无关。
  所以「链接过期」不会把任何人踢出去。
- **群主自己的码永不失效**。这是为了让改版前发出去的旧链接继续能用；
  否则所有老群的同学会在某天突然进不来。想作废它就点管理页里的「换一个新码」。
- **过期给 410、无效给 404**，文案也不同：「已经过期，找群主要个新的」
  vs「链接无效，确认是不是少复制了数字」。用户据此就知道该找谁。
- **作废只标记，删除才真抹掉**。留档才能事后回答「这个码是谁什么时候发的」，
  所以默认作废，管理页里再显式删除；而且只有已失效的才能删，免得一步误操作把正在用的链接弄没。
- **作废过的码永远不会被重新发出来**。发新码时会避开全部历史记录——
  否则作废码被撞上重发，拿到旧链接的人会莫名其妙重新获得入口。
- 同时最多 20 条**还能用**的链接；作废/过期的不占配额，所以不用急着清历史。

### 换群自己的码

改版前建的群，码是 **6 位**（10⁶ 空间）。配 20 次/分钟的限流，枚举完只要一个多月，
比 8 位的「上百年」弱得多。管理页里的「换一个新码」可以把它换成 8 位，
代价是**以前发出去的所有链接一起失效**，需要把新码重新发给还没进群的同学。

实现上只改 `g.code`、**不动文件名**：文件名是内部存储键，改它就要 rename，
而 rename 跨崩溃不原子，失败一次群就丢了。代价是码和文件名会分家，
所以所有按码取群的路径都走 `resolveGroupFile()`（先按文件名试，再扫 code 字段），
换过码的群照样能正常改设置、移人、发链接。

## 部署详解

### 正式服长什么样

```
浏览器 ──HTTPS──> 反向代理 ──HTTP（只走本机环回）──> 容器 127.0.0.1:3560 ──> node server.js :3000
   站点路径 /tongge/           剥离前缀后再转发 /api/*、/shared/*、静态文件
```

三条硬性约定，反代必须照做，否则页面会白屏或接口 404：

1. **站点挂在子路径下**（`/tongge/`）时，反代要把 `/tongge/` 这段前缀**剥掉**再转给容器：
   `/tongge/api/me` → `/api/me`。前端用的是相对路径，正是为此
2. **容器端口不要直接对外**：compose 默认 `127.0.0.1:3560:3000`，只允许本机反代连
3. **HTTPS 由反代终止**：证书、跳转都在反代那层；容器里跑的是明文 HTTP，但只在环回上，不出网

#### 谁能访问

这取决于你把服务放在哪，**跟「是不是同一个 WiFi」无关**：

| 部署方式 | 谁能打开 |
|---|---|
| 正式服挂在公网（现状） | **任何人拿到地址都能打开、能注册**。群组内容靠邀请码保护，不靠网络隔离 |
| 只在内网 / 校园网 / VPN 里暴露 | 取决于你能不能连到那台机器所在的网络 |
| 本机 `node server.js`（开发 / 预览） | 同网段的设备能访问——这是唯一还适用「同一个网络」的场景 |

本机开发 / 预览不需要反代：`node server.js` 打开 `http://localhost:3000` 就行。

### 本机跑（开发 / 预览）

**用途**：改前端、跑测试、看效果，不需要 Docker 也不需要反代。

```bash
node server.js              # 默认 3000
node server.js --port 3001  # 换端口
```

- 零 npm 依赖，**不要**跑 `npm install`（跑了也不会装出任何东西）。
- 数据写在项目目录的 `data/` 里；换个目录跑就是另一套数据。
- **关掉终端窗口服务就停了**——所以正式服走 Docker，不用这个跑法。
- 服务绑 `0.0.0.0`，同网段的其他设备也能用 `http://<本机IP>:3000` 访问；
  Windows 首次运行会弹防火墙提示，选「允许访问」。

### Docker 部署（正式服用这个）

**它要解决的问题**：直接跑的话「代码」和「数据」混在一起，换台机器、重建容器，
账号和课表就没了。这一节把 Docker 化过程中踩到的坑和对应做法讲清楚——
`entrypoint.sh` 和 `Dockerfile` 里那些看起来多余的注释，都是在防下面这几件事。

#### 问题 1：容器一重建，数据就没了

- **问题**：运行期数据写在容器内，`docker rm` 或换镜像版本后全部消失。
- **怎么解决的**：数据落在命名卷 `tongge-data`，容器只是「跑代码的壳」。
  容器重建、升级镜像都不动数据。
- **你要做的**：compose 里保留 `- tongge-data:/app/data` 这一行。
  `docker compose down` **不会**删卷；要把数据一起删掉得显式写 `docker compose down -v`。

#### 问题 2：想把现有的一批账号/群组一起带过去，但又不能每次启动都覆盖

- **问题**：镜像里烧进 `data/` 就能「带着数据上线」，可是如果启动时无脑覆盖到运行目录，
  第二次启动就会把同学新传的课表冲掉。
- **怎么解决的**：镜像把 `data/` 放在 `/opt/seed`（**不是**直接放 `/app/data`），
  `entrypoint.sh` 只在「卷里还没有数据」时铺一次，之后永远跳过。
- **你要做的**：什么都不用做，看日志确认即可：

  ```
  [entrypoint] 首次启动：把镜像自带的种子数据铺到 /app/data
  [entrypoint] 数据卷里已有数据，跳过种子铺入（不会覆盖现有账号与群组）
  ```

  日志还会打印这次到底带入了多少个账号 / 群组 / 会话，以及是否包含会话表。

#### 问题 3：「卷里有没有数据」怎么判断才可靠

- **问题**：只看「目录空不空」不够稳——有些环境会先塞进 `lost+found` 之类的东西，
  于是永远被判成「已有数据」，种子一次都铺不进去。
- **怎么解决的**：认 `users.json` / `sessions.json` 是否存在，或 `groups/` 里有没有文件。
- **你要做的**：无。

#### 问题 4：`cp` 会把权限一起复制，导致铺完写不进去

- **问题**：如果种子（或将来有人把种子目录改成只读）没有写位，铺到卷上之后
  `node` 用户写不进 `users.json`——表现是**注册、传课表全线 500**，
  而且报错信息很难指回这里。
- **怎么解决的**：铺完统一修一次属主 / 写位（`chown` 或 `chmod u+rwX`，只给属主加位），
  目录本身收窄到 `0700`；最后用 `touch` 做一次**真实写入测试**，
  写不进去就立刻退出并直接打印修法。
- **你要做的**：如果你把挂载改成了 bind mount（`./data:/app/data`），
  按日志给的提示执行 `sudo chown -R 1000:1000 ./data`。
  **推荐直接用命名卷**，这类问题一次都不会遇到。

#### 另外三件顺手解决的小事

- **`tini`**：容器里 PID 1 需要有人转发信号。少了它，`docker stop` 会等满 10 秒然后 `SIGKILL`，
  关服钩子里的会话表落盘就跑不到，大家最后的登录状态会丢。
- **健康检查**：`HEALTHCHECK` 打 `/api/meta`（唯一不需要鉴权的接口）当探针。
- **日志别无限涨**：compose 里把 json-file 日志限制成 `10m × 3` 个文件。

#### 你要做的：三条命令

```bash
docker compose up -d --build     # 构建 + 启动
docker compose logs -f tongge    # 看启动横幅
docker compose down              # 停服务（卷保留，数据不丢）
```

然后在反代里把站点指到 `127.0.0.1:3560`（子路径要把前缀剥掉，见上一节）。

不用 compose 也可以：

```bash
docker build -t tongge:1.0 .
docker run -d --name tongge \
  -p 127.0.0.1:3560:3000 \
  -v tongge-data:/app/data \
  --restart unless-stopped \
  tongge:1.0
```

> 想在还没配反代的机器上直接打开看，把端口换成 `-p 3000:3000`（compose 里同理），
> 再访问 `http://<主机>:3000`。**公网机器上别这么干**——那是明文直连。

#### 只想让账号和群组过去，不带任何活跃登录态

`data/` 里的 `sessions.json` 存的是**明文会话令牌**。要交给别人构建、或者想让镜像干净一点，
可以把它剔掉（代价：所有人需要重新登录一次）：

```bash
docker build -t tongge:1.0 --build-arg INCLUDE_SESSIONS=false .
```

用 compose 的话，把 `docker-compose.yml` 里的 `INCLUDE_SESSIONS: "true"` 改成 `"false"`。

```

  发起人     DongLanQwQ
  ─────────────────────────────────────────────
  本机访问   http://localhost:3000
  正式服     对外由反向代理提供 HTTPS，站点形如 https://<主机>/tongge/
             这里不再打印网卡地址：正式服的入口是反代，不是本机端口。
```

以前它会把探测到的局域网地址（`http://10.x.x.x:3000`）打出来，好让你发给同学；
现在正式服的入口是反代，那段网卡探测已经删掉了。

#### ⚠️ 不要改 `DATA_DIR`

入口脚本**按 `DATA_DIR` 铺种子**，但服务本身读写的是**代码旁边的** `data/`
（容器里就是 `/app/data`，因为工作目录固定在 `/app`）。把这个变量指到别处，
就会出现「种子铺到 A、服务写 B」——看起来就是**账号凭空消失**。

**要换数据位置，请改挂载点，不要改这个变量。**

### 数据放在哪

运行期数据在 `/app/data`（命名卷 `tongge-data`）。**镜像里不带数据了**：
早期版本把 `data/` 烧进 `/opt/seed`，好让首次部署自带账号，代价是镜像层里留着
密码哈希和明文会话令牌——镜像会被推 registry、被复制、被留档，那等于把站点交出去。
现在改成显式导入（想带旧数据时手动做一次）：

```bash
docker run --rm -v tongge-data:/data -v "$PWD/data:/seed" alpine \
  sh -c 'cp -R /seed/. /data/'
```

`entrypoint.sh` 仍然支持 `/opt/seed`（有就铺、卷里非空就绝不动），所以那条老路照样能用：

| 场景 | 行为 |
|---|---|
| 首次启动，卷是空的、又没有种子 | 从空库开始（第一个注册的人可以 `--super` 设为超管） |
| 首次启动，卷是空的、`/opt/seed` 有东西 | 铺入种子，同学不用重新注册 |
| 容器重启 / 换镜像版本 | **跳过铺入**，同学新传的课表与账号一个不动 |
| 卷里只有 `groups/` | 认作「已有数据」，同样跳过 |

判断依据是 `users.json` / `sessions.json` 是否存在，或 `groups/` 里有没有文件——
不是「目录是否为空」，免得被 `lost+found` 之类的东西误判。

### 存储加密与迁移

**现状**：昵称、课表、私密备注、群内对外备注在盘上是密文，钥匙是根密钥
`TONGGE_ROOT_KEY`（`/etc/tongge/key.env`，在部署目录之外）。挡的是"数据卷/备份/
部署包/镜像被拿走"；**挡不住拿到执行权限的人**（运行时钥匙必须在内存里）。
取舍与理由见 `docs/superpowers/specs/2026-09-17-storage-encryption-design.md`。

**从旧版本升级上来**（部署方式是用仓库代码覆盖，所以顺序不能错）：

```bash
# 0. 备份（数据在命名卷里）
docker run --rm -v tongge-data:/data -v "$PWD:/backup" alpine \
  tar czf /backup/tongge-$(date +%Y%m%d-%H%M).tar.gz -C /data .

# 1. 根密钥（首次才需要；已经有 /etc/tongge/key.env 就跳过）
#    ⚠️ 必须先做这一步：compose 里的 env_file 指向它，文件不存在时
#    连 docker compose stop 都会因为"env file not found"直接报错
# 服务器上一般没装 node（应用跑在容器里），所以用容器生成一把
KEY=$(docker run --rm node:22-alpine node -e "console.log(require('crypto').randomBytes(32).toString('hex'))")
sudo install -d -m 700 /etc/tongge
printf 'TONGGE_ROOT_KEY=%s\n' "$KEY" | sudo tee /etc/tongge/key.env >/dev/null
sudo chmod 600 /etc/tongge/key.env

# 2. 代码就位
cd /opt/tongge && git pull

# 3. 停服务 —— 这一步不能省：运行中的进程内存里是明文，
#    任何一次写入都会把迁移结果覆盖回明文
docker compose stop

# 4. 先构建新镜像 —— 也不能省。`docker compose run` 用的是**镜像里**的代码：
#    不先构建，跑的还是旧代码，它不认识 --migrate-vault，会当成普通启动把
#    服务跑起来（表现为"卡住不动，只打印横幅"）
docker compose build

# 5. 迁移（CLI 模式，不启 HTTP；缺根密钥会直接报错）
docker compose run --rm tongge node server.js --migrate-vault --super DongLan

# 6. 起服务（镜像已是新的，不必再加 --build）
docker compose up -d

# 7. 抽查：卷里搜不到任何备注原文（引号里换成你自己知道的一条）
docker run --rm -v tongge-data:/data alpine \
  grep -rl "某条备注原文" /data || echo "文件里已无该明文 ✓"

# 8. 确认备份可用后，删掉迁移留下的明文副本
docker run --rm -v tongge-data:/data alpine sh -c 'rm -f /data/*.plaintext-*'
```

迁移是**幂等**的，重复跑不会重复加密；服务启动时若发现还有明文，会**拒绝启动**并提示
跑上面第 5 步——免得"一半明文一半密文"的状态悄悄上线。

会话令牌也在这次升级里换成了 sha256 落盘（`sessions.json` 的键），**同学不需要重新登录**。

> 备份 tar 里是**迁移前的明文**（含姓名与备注）。要么把它放在受控位置（`chmod 600`），
> 要么确认无误后删掉——别随手丢在共享目录里。

### 反向代理与 HTTPS（现状）

**现在的做法**：反代终止 TLS，容器只监听本机环回。这一节记的是这套配置里几处容易出错的地方。

| 事项 | 现状 / 风险 | 怎么办 |
|---|---|---|
| 传输加密 | 反代负责 HTTPS；容器内部是明文 HTTP，但只在 `127.0.0.1` 上，不出网 | 证书与跳转都在反代那层配，容器不用改 |
| 真实 IP | 已支持：直连方属于可信网段时才采信 `X-Forwarded-For`，并从右往左取第一个不可信地址 | 可信网段默认「本机 + 容器网段」，用 `TONGGE_TRUSTED_PROXIES` 收窄；见下面「关于真实 IP」 |
| 子路径 | 站点在 `/tongge/` 下，反代必须在转发前剥掉这段前缀 | 否则 `/tongge/api/me` 原样转给容器，接口 404 |
| 任何人都能注册 | 公网上会被批量灌号（现在只标注「可疑注册」，不拦截） | 加一道站点访问口令，或限制来源（校园网 / VPN） |
| 数据里有密码哈希与明文令牌 | 容器被翻 = 全员账号 | `data/` 已收窄到 `0700`；卷不挂到宿主机目录 |

**最小可用的反向代理示例**（示意，按自己的环境改）：

```nginx
server {
    listen 443 ssl;
    server_name tongge.example.com;
    # ssl_certificate / ssl_certificate_key ...

    # 子路径部署：/tongge/ 这段前缀要剥掉
    location /tongge/ {
        proxy_pass http://127.0.0.1:3560/;      # 结尾这个斜杠就是「剥掉前缀」
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

> `proxy_pass` 结尾那个斜杠很关键：带斜杠才会把 `location` 匹配到的前缀替换掉。
> 少了它，容器收到的是 `/tongge/api/me`，而它只认 `/api/me`。

#### 关于真实 IP

限流要按**真实来源**分桶，否则反代后面所有人的请求都算在同一个桶里：一个人刷满阈值，
其他人会一起收到「请求太频繁了」——注册那边更直接，9 次尝试就能让**全站**十分钟注册不了。

规则只有一条：**只有当直连方本身属于可信网段时，才看 `X-Forwarded-For`**。
可信时从**右往左**找第一个不可信地址（最左边那个是客户端自己填的，认它等于认攻击者写的值）；
直连方不可信就完全不看那些头，只用 TCP 来源地址——否则谁都能伪造一个 IP 绕过全部限流。

可信网段默认是「本机 + 容器网段」（Docker 里反代连进来时，容器看到的源地址是网桥网关），
需要收窄或关掉时用环境变量：

```bash
TONGGE_TRUSTED_PROXIES="127.0.0.1,10.0.0.0/8"   # 只信这些
TONGGE_TRUSTED_PROXIES="none"                    # 谁都不信（只看直连地址）
```

> ⚠️ 默认值为了开箱即用放得比较宽。**如果这个端口还对局域网开放、或同网段跑着不受信任的容器**，
> 必须用上面这个变量收窄——否则同网段的人可以自己填 `X-Forwarded-For` 绕过限流。
> 启动横幅会打印当前生效的模式（`限流依据 …`），部署完扫一眼那行。

### 备份与恢复

**它要解决的问题**：数据全在卷里，`users.json` 是唯一的真身。误删、写坏、要迁机器，
没有备份就只能重来。

**日常冷备一条命令**：

```bash
docker run --rm -v tongge-data:/data -v "$PWD:/backup" alpine \
  tar czf /backup/tongge-$(date +%Y%m%d).tar.gz -C /data .
```

**恢复**：把 tar 解开到卷里，**先 `docker compose stop`**，再起。

另外程序本身每次写 `users.json` / `sessions.json` 都会留一份 `.bak`，
文件损坏时会自动从 `.bak` 恢复——但那是防「写坏」，**不防「误删」**，两者都要有。

### 部署常见故障排查

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 页面能打开，但接口全 404 | 反代没把子路径前缀剥掉 | 给 `proxy_pass` 结尾加斜杠（见上面的反代示例） |
| 页面白屏 / 样式和脚本加载失败 | 站点挂在子路径，反代却把 `/tongge/...` 原样转给了容器 | 同上。前端用的是相对路径，剥掉前缀就正常 |
| 本机 `curl 127.0.0.1:3560` 正常，外面访问不了 | 反代没起、指错端口，或证书过期 | 确认反代指向 `127.0.0.1:3560`，证书有效 |
| 一个人刷太频繁，所有人都被限流 | 限流键取错了来源：反代后面要按真实 IP 分桶 | 已默认支持；若同网段还有不受信任的来源，用 `TONGGE_TRUSTED_PROXIES` 收窄（见 [关于真实 IP](#关于真实-ip)） |
| 注册 / 传课表出错，日志里有 `EACCES` | `data/` 不可写（bind mount 属主不对） | 按入口脚本打印的提示 `sudo chown -R 1000:1000 <映射目录>`，或改用命名卷 |
| 数据「凭空消失」 | 把 `DATA_DIR` 指到了 `/app/data` 之外，或挂载点写错 | 数据固定写在 `/app/data`；**改挂载点，别改 `DATA_DIR`** |
| 端口被占用（`EADDRINUSE`） | 3000 或 3560 已被别的程序用了 | 本机跑：`node server.js --port 3001`；Docker：改 compose 里 `"127.0.0.1:3560:3000"` 的宿主机那一段 |
| 群里换了码，但 `data/groups/` 下的文件名对不上 | 换码只改 `code` 字段、不动文件名，这是有意的 | 排查时**以文件里的 `code` 字段为准**，别按文件名找群 |
| `docker stop` 要等很久 | 自定义镜像时去掉了 `tini`，信号传不到 node | 别删 Dockerfile 里的 tini 与 `stop_grace_period: 15s` |

## 安全上的几个决定

写在这里，免得以后有人「顺手优化」把它们改没：

- **改密码与登录一样有刹车**：旧密码连错 5 次（`loginFail` 限流）就锁。没有它的话，
  抓到一次会话令牌就能无限猜旧密码，猜中即永久接管账号。
- **只接受 `application/json` 请求体**，其余一律 415。`text/plain` 是浏览器表单能发、
  又不触发 CORS 预检的类型——现在令牌走 `Authorization` 头所以还安全，
  但哪天改成 Cookie，这道校验就是 CSRF 的最后一道门。
- **像文件、或形状像穿越的路径一律 404**，不再回落首页。否则「被挡住」和
  「真的读到了源码」在响应上长得一模一样，安全结论只能靠人肉比对响应体长度。
- **内部错误只回固定文案**。`fs` 抛的原文里有 errno，有时还带绝对路径，不该给攻击者看。
- **`/shared/*` 是白名单**，不是整个目录。`auth.js` / `store.js` 的注释都写着
  「仅服务端使用」，白名单让这句话变成代码事实。
- **会话表常驻内存**，读请求不再重写整张表（此前每次鉴权都要全量重写，
  实测慢 19 倍且全局串行）。`lastSeen` 攒够一分钟或定时器到点才落盘。
- **`users.json` / `sessions.json` 每次写完留一份 `.bak`**，损坏时优先恢复——
  否则会话表一坏就是「全员被强制登出」。
- **响应头**：`nosniff`、`X-Frame-Options: DENY`、`no-referrer`，以及一条
  只允许自身资源的 CSP。
- **限流按真实来源分桶**：站点在反代后面时，`socket.remoteAddress` 是反代/网桥地址，
  于是所有人挤在同一个桶里（一个人刷几次注册就能让**全站**十分钟注册不了）。
  现在只在该直连方**属于可信网段**时才采信 `X-Forwarded-For`，而且是**从右往左**取
  第一个不可信地址——最左边那段是客户端自己填的，认它等于认攻击者写的值。
  可信网段用 `TONGGE_TRUSTED_PROXIES` 收窄或写 `none`。
- **敏感字段落盘加密**：昵称、课表、私密备注、群内对外备注都用 `TONGGE_ROOT_KEY`
  这一把根密钥加密后才写盘（`AES-256-GCM`，AAD 绑住"用途 + 归属"，所以把课表的密文
  冒充备注、把甲群的对外备注挪到乙群都会解密失败）。读进内存才解密，所以业务代码
  一行没改。**代价说清楚**：它挡的是"数据卷 / 备份 / 部署包 / 镜像被拿走"，
  **挡不住拿到执行权限的人**——运行时钥匙必须在内存里，这是信息论限制。
  根密钥必须放在部署目录之外。设计见 `docs/superpowers/specs/` 里那份存储加密文档。
- **会话令牌只存 sha256**：`sessions.json` 的键是令牌的哈希，明文令牌只在签发那一刻
  存在过。此前明文落盘，等于「拿到这个文件就能冒充任意登录用户，连密码都不用」。
- **注册验证码自己画**：算式是**画进像素**的（不是 SVG 的 `<text>`），
  所以响应里只有一张图，想读答案得认图；题目 3 分钟过期、**一次一废**，
  答错也作废，拿同一个 id 反复试答案这条路被堵死。
  自己画还顺带保住了零依赖：不用 canvas 那类原生模块，PNG 是 `node:zlib` + 自算 CRC32 出来的。
- **进程级兜底**：未捕获异常会记审计日志再退出，而不是无声无息地让所有同学掉线。

## 已知限制

- **容器内部是明文 HTTP**：TLS 由反代终止，容器只监听 `127.0.0.1`，所以流量不出网；
  但**反代那层必须配好 HTTPS 与跳转**，否则「浏览器到反代」这一段就是明文，令牌可被抓。
  ⚠️ 反代配置或证书一旦出问题，站点会直接退回明文——这是整套部署里最需要盯的一环。
- **反代之后要认真实来源**：只看直连方可信网段时的 `X-Forwarded-For`（见
  [关于真实 IP](#关于真实-ip)）。默认可信网段是「本机 + 容器网段」，**端口若还对
  局域网开放、或同网段跑着不受信任的容器，必须用 `TONGGE_TRUSTED_PROXIES` 收窄**，
  否则同网段的人伪造一个头就能绕过限流。
- **本机直接跑（`node server.js`）时没有 HTTPS**，只在开发 / 预览时这么用，别当正式服。
  这种跑法下 `data/` 的权限是从父目录继承的，Windows 上默认「本机所有用户可读」，
  而 `sessions.json` 里存的是会话令牌的 sha256（明文令牌不落盘），`users.json` 里的
  姓名/课表/备注是密文——但**根密钥还是本机的环境变量**，所以同一台电脑上的其他人
  只要读得到它就能解密。**如果这台电脑还有别人用**，请手动收权：

  ```
  icacls data /inheritance:r /grant:r "%USERDOMAIN%\%USERNAME%:(OI)(CI)F"
  ```

  （Windows 上 Node 的 `chmod` 是空操作，改代码没用，只能走 ACL。）
- **任何人都能打开站点并注册账号**，只靠邀请码保证群组内容不外泄。
  在公网正式服上这条更值得注意：会被批量灌号（现在只标注「可疑注册」，不拦截）。
- **注册验证码的边界**：它挡的是「随手写个脚本灌号」，**挡不住**愿意上 OCR / 打码平台的人；
  和按 IP 的注册限流是叠加关系，不是替代。另外**读屏用户做不了图片验证码**——
  兜底是「群主审批入群」加低频限制。要在本机开发时关掉它：
  `createServer({ captcha: false })`（测试就是这么跑的）。
- **邀请码是 8 位数字**（改版前的 6 位老码仍然可用，已发出的链接不会失效）。
  加入接口按来源 IP 限流 20 次/分钟——8 位码在这个速度下枚举完要上百年，够用了。

  > 改版前那批 6 位老码只有 10⁶ 空间，同样限流下**枚举完约 35 天**，明显更弱。
  > 群里还有人的话，用管理页里的「换一个新码」换成 8 位；老链接会一起失效，
  > 但先进来的人不受影响。
  > 另外要注意：换群自己的码之后，**群文件名仍是旧码**（那是内部存储键），
  > 所以 `data/groups/` 下的文件名不一定等于群码——排查时以文件里的 `code` 字段为准。
- 全站接口另有 600 次/分钟的 IP 限流，注册 8 次/10 分钟 + 20 次/小时。
  阈值放得很宽，正常使用碰不到。
- 请求体上限 1MB；**超限时会先把多余的部分读完再回 413**（4 倍以内），
  这样客户端收得到明确提示，而不是稀里糊涂地「连接被重置」。

## 给开发者：接口一览

服务端是 `server.js` 里一张路由表，鉴权走 `Authorization: Bearer <token>`。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/meta` | 健康探针：`{ ok, app, tagline }`。唯一免鉴权接口，Docker 健康检查也打它 |
| GET | `/api/captcha` | 注册验证码：`{ enabled, id, image }`，`image` 是一张 PNG 的 data URL |
| POST | `/api/register` `/api/login` `/api/logout` | 账号（注册要带上 `captchaId` + `captchaAnswer`） |
| GET / DELETE | `/api/me` | 当前账号 / 注销 |
| PUT | `/api/me/courses` `/api/me/password` | 上传课表 / 改密码 |
| PUT | `/api/me/remarks/:targetId` | 个人备注（只有自己可见） |
| GET | `/api/me/groups` | 我加入的群 |
| POST | `/api/groups` | 建群 |
| POST | `/api/groups/:code/join` | 入群（或提交申请） |
| GET | `/api/groups/:code` | 群详情（含重合统计） |
| PUT | `/api/groups/:code/settings` | 群设置（改名 / 入群策略 / 备注） |
| POST | `/api/groups/:code/rotate-code` | 换群码 |
| POST / DELETE | `/api/groups/:code/invites…` | 邀请链接：新建 / 作废 / 删除存档 |
| POST / DELETE | `/api/groups/:code/requests/:userId` | 审批进群申请 |
| DELETE | `/api/groups/:code/members/:userId` | 移除成员 |
| GET | `/api/admin/overview` | 管理员视图：账号 / 群组 / 审计 |
| PUT / DELETE / POST | `/api/admin/users/:id…` | 授权、删除账号、重置密码 |
| POST / DELETE | `/api/admin/groups/:code…` | 换群码、解散群组 |

授权管理员走命令行（因为这是**本机操作**——能敲这条命令就说明你本来就摸得到 `data/`）：

```bash
node server.js --make-admin 你的昵称     # 设为管理员
node server.js --revoke-admin 你的昵称   # 取消管理员
```

先在网页上把账号注册出来，再执行这条命令。

## 版本管理与推送

**只推送 `main` 分支。**

```
main            要推送的分支，干净的起点（单个初始提交）
local-archive   早期开发历史，仅本地保留，永不推送
```

为什么这么分：仓库根目录那几份真实课表虽然已经被 `.gitignore` 挡在库外，但**早期提交里
还留着同学的真名**（当时的测试夹具和文档）。与其重写历史（会改掉全部提交哈希），
不如从当前这份已经全部化名的状态重新起一个根提交，只把这个提交推上去。

⚠️ **不要用 `git push --all`，也不要用 GUI 里的「推送所有分支」**——那会把
`local-archive` 连它背后的 44 个提交一起推上去，化名就白改了。

```bash
git remote add origin <你的仓库地址>
git push -u origin main
```

之后正常 `git add` / `git commit` / `git push` 就行，历史会从 `main` 这个根提交往后长。

## 后续规划

方向、坑和优先级写在 **[docs/ROADMAP.md](docs/ROADMAP.md)** 里，那里每一条都标了
「现在是什么样」，免得误以为已经做过了。摘要（按优先级）：

1. **备份 + 写前快照**——成本最低，救的是最不可逆的损失
2. **限流改成按真实 IP / 按账号双轨**（真实 IP 已支持，见 [关于真实 IP](#关于真实-ip)；
   「按账号」那一轨还没做）
3. **超时与抗打加固**（`headersTimeout` / `requestTimeout` / 单 IP 并发上限）
4. **审计聚合与自动封禁**——在有人开始攻击之后再补就晚了
5. **接入学校身份认证**——收益大但外部依赖重，可以晚
6. **课表匹配（找相似课表的人）**——功能上最有意思，风险上也最重，放最后且单独评审

> ~~传输加密~~ **已完成**：正式服由反向代理提供 HTTPS，容器只监听本机环回。

> 第 6 项要注意：现在的可见范围是「同群成员」，本质上是熟人网络。
> **一旦开放陌生人匹配，就从「熟人可见」变成「陌生人可见」**，
> 而课表里含真实姓名、每周行踪、常去的楼栋教室。这条上线前应当单独做一次评审。
