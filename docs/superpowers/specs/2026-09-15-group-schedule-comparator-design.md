## 1. 背景与目标

在使用者的真实课表（仓库根目录三份 `.ics`，浙大 Elychron 导出，各 200+ 事件）上，
需要一个能回答「我和谁、在哪节课、教室离得多近」的工具。

产品形态：

1. 注册一个账号（**昵称 + 密码**，全局唯一）。
2. 上传自己的 `.ics` 课表，解析后存在服务器上，归属于账号。
3. 创建群组 → 得到 6 位邀请码 + 二维码；同学凭邀请码入群。
4. 群组页列出全体成员，**每人直接显示与我的重合课时数，并按地点等级分类**。
5. 点任一成员 → 与该成员做双人网格比对 → 导出高清图片。

同时修掉 v1 在真实数据上暴露的三个问题：

1. 中文楼栋（`紫金港化学实验中心-424`）被误判为「特殊地点」，比对结论错误。
2. 单双周课程在同一格子有两处地点，v1 取 `cellData[0]` 会静默丢弃第二处。
3. 需求文档中的「组团」判定完全未实现。

## 2. 范围

**做**：全局账号（昵称 + 密码，scrypt 加盐哈希）、会话令牌、课表上传与更新、群组创建/加入/退出/解散、
邀请码 + 二维码、群组成员重合课时数按等级统计、双人网格比对、周次切换与单双周自动选择、
高清图片导出、局域网访问、服务端持久化。

**不做**（YAGNI）：手机号/邮箱验证、找回密码、第三方登录、跨网访问、N 人同格叠加、
课表冲突检测、自动对接教务系统、消息通知、HTTPS 证书自动化。

## 3. 技术栈与形态

- 后端：**Node.js，零 npm 依赖**（只用 `node:http` / `node:fs` / `node:crypto` / `node:os` / `node:path`）。
  `node server.js` 即可启动，无需 `npm install`。
- 前端：原生 JS + CSS，无框架，多屏路由。
- 解析：**浏览器端解析 `.ics`**，只把结构化 JSON 传给服务端。
  理由：服务端无需处理 multipart；`shared/ics.js` 一份代码前后端与微信小程序三处复用。
- 第三方库：`html2canvas`、二维码生成器**下载到 `public/lib/` 本地内置**，不依赖 CDN
  （局域网同学可能无外网，导出功能必须离线可用）。
- 持久化：JSON 文件（详见 §7）。**不存原始 `.ics`**，只存解析后的结构化课表。
- 绑定 `0.0.0.0:3000`（可用 `PORT` 环境变量覆盖），启动时打印全部局域网 IP 及访问地址。

## 5. 数据模型

### 5.1 用户 `data/users.json`

```json
{
  "v": 1,
  "users": [
    {
      "id": "u_7f3a91",
      "nickname": "小灰",
      "pwAlgo": "scrypt",
      "pwSalt": "a1b2…",          // 16 字节随机，hex
      "pwHash": "9f2c…",          // scrypt(password, salt, 64) 的 hex
      "createdAt": 1757900000000,
      "updatedAt": 1757900000000,
      "courses": [
        {
          "course": "大学英语Ⅲ",
          "day": 1,
          "startPeriod": 3,
          "endPeriod": 4,
          "startTime": "10:00",
          "endTime": "11:35",
          "location": "紫金港东6-328",
          "dates": ["20260914", "20260921", "20261012"]
        }
      ]
    }
  ]
}
```

- **课表是账号属性，不是群组成员属性**——同一账号加入多个群时课表自动复用，无需重复上传。
- `nickname` **全局唯一**（比较时忽略大小写、去首尾空白，展示时保留原样），作为登录标识。
- `dates`：该课槽位**实际发生的日期**（`YYYYMMDD`）。同一门课的多次周重复合并进同一槽位。
  单双周、调休、临时加课无需任何奇偶推算，天然正确。
- 槽位合并键：`course | day | startTime | endTime | location`，合并时 `dates` 取并集去重排序。

### 5.2 群组 `data/groups/<code>.json`

```json
{
  "v": 1,
  "code": "483920",
  "name": "计科2201组团",
  "creatorId": "u_7f3a91",
  "createdAt": 1757900000000,
  "updatedAt": 1757900000000,
  "members": [
    { "userId": "u_7f3a91", "joinedAt": 1757900000000 }
  ]
}
```

群组只保存成员引用，成员昵称与课表实时从 `users.json` 取，保证改一次名处处生效。

### 5.3 会话 `data/sessions.json`

```json
{
  "v": 1,
  "sessions": {
    "3b81c0…": { "userId": "u_7f3a91", "createdAt": 1757900000000, "lastSeen": 1757900000000 }
  }
}
```

- 令牌：`crypto.randomBytes(32).toString('hex')`，登录/注册时签发。
- 前端把令牌存 `localStorage`（key `dsh_token`）——这就是「浏览器本地保存状态」。
- 有效期 90 天，滑动续期（每次带令牌的请求刷新 `lastSeen`）；过期或不存在返回 `401`。
- 改密码或显式登出时吊销该用户全部令牌。

### 5.4 体积估算

单份真实课表约 250 个事件 → 合并后 35–40 个槽位，`dates` 合计约 250 个日期，约 3 KB/人。
50 个账号约 150 KB，30 人群组约 1 KB，文件存储完全够用。

## 6. 周次与单双周

- **教学周基准**：取参与的双方（或全群）所有 `dates` 的最小日期，回退到该日期所在周的周一，为「第 1 周」。
- **年内周次**：另有 `yearWeekOf(date)` 给出该日期在自然年里的 ISO 周次（含 1 月 4 日的那周为第 1 周）。
  周次胶囊同时显示两者（`第 3 周 · 年 40 周`）。原因：教务导出的 `.ics` 里混有调休补课、期末考试等
  零散日期，会把「最早日期」提前、使教学周编号整体偏移；年内周次只由日期决定，可作绝对参照。
  **单双周一律按教学周基准判定**（与学校口径一致），与年内周次无关。
- **调休说明**：课表页周次下方常驻一行说明，解释两个数字的含义，并声明个别日期可能落在常规教学周
  之外（调休、补课、考试），课表按 `.ics` 里的真实日期显示。
- **当前周**：以浏览器当天日期所在周（周一至周日）为目标周。
- **显示规则**：只渲染 `dates` 落在目标周内的槽位。单双周未命中的槽位整格不显示。
- **跨周兜底**：若当前周双方合计 0 节课（寒暑假/考试周），自动回退到「最近的有课周」，
  顶部提示条显示 `当前周无课，已显示 第 N 周`。
- **周次胶囊**：两行。第一行教学周，第二行「具体日期 + 年内周次」，例如
  `第 1 周` / `本周 · 9/14~9/20 · 年38周`。日期必须直接写出来 —— 手机上没有悬停，
  放进 title 等于没有。今天所在的那一周额外加一圈描边，手动切走之后也认得出。
- **默认选中**：进页面时按**当前日期**定位到本周（`resolveDefaultWeek`）；本周双方都没课时，
  退回到距今天最近的有课周，并给一行提示。
- **周次切换器**：顶部一排周次胶囊（第 1 周 … 第 N 周），默认停在当前周或兜底周；
  手动切换后进入「手动模式」，不再跟随今天。选择结果存 `localStorage`。
- **一致性要求**：群组页的重合课时数与比对页的网格**必须使用同一个选中周**，两处共用一个周次状态。
- **屏幕与导出解耦**：以上「选中周」规则**只作用于屏幕**。导出图片固定使用「全学期代表周」
  （§12），不受周次切换器影响，因此导出的图长期有效、不因导出日期而变。

## 7. 服务端存储（`shared/store.js`）

- **原子写**：先写 `<file>.tmp` 再 `fs.rename` 覆盖，避免半截文件。
- **写队列**：`users.json` / `sessions.json` 各一条全局 Promise 链，每个群组文件一条，
  读-改-写串行化，杜绝并发覆盖（Node 单线程但 `await` 之间仍会交错）。
- **读损坏兜底**：`JSON.parse` 失败时重命名为 `<file>.corrupt-<ts>` 保留证据，记录日志并重建空库，不静默丢数据。
- **邀请码**：`crypto.randomInt(10000000, 100000000)` **八位**数字；生成时若文件已存在则重试（上限 10 次）。
  校验同时接受 6 位 —— 位数改版前发出去的链接不能失效（`/^\d{6}$|^\d{8}$/`）。
- **密码**：`crypto.scrypt(password, salt, 64)` 异步版本（`promisify`，不阻塞事件循环），
  参数 N=16384, r=8, p=1；比较用 `crypto.timingSafeEqual`。**任何日志、响应、文件中都不得出现明文密码**。
- **输入校验**（服务端强制，不信任前端）：
  - 邀请码 `/^\d{6}$|^\d{8}$/`
  - 昵称：去首尾空白、剔除控制字符与 `/\\:*?"<>|`，长度 1–10，全局唯一
  - 密码：长度 6–64，不得为纯空白
  - `courses`：数组，长度 ≤ 500；每条必须含合法 `day`(1-7)、`startPeriod`/`endPeriod`(1-13)、
    `startTime`/`endTime`(`HH:MM`)、`location`(≤ 100 字符)、`dates`(长度 ≤ 60，元素 `YYYYMMDD`)
  - 请求体 ≤ 1 MB；群组成员数 ≤ 50
- **登录节流**：同一昵称连续失败 5 次锁定 60 秒（内存计数，重启即清）；
  失败响应统一为「昵称或密码不对」，不区分二者，避免账号枚举。
- **过期清理**：会话 90 天未活动删除；`updatedAt` 超过 180 天的群组在启动时及每日定时删除。
- **静态文件**：只从 `public/` 提供；路径做 `path.normalize` + 前缀校验，防目录穿越。

## 8. HTTP API

JSON 收发。需要登录的接口带 `Authorization: Bearer <token>`。
错误统一 `{ "error": "人类可读的中文原因" }` + 对应状态码。

### 账号

| 方法 | 路径 | 请求体 | 响应 |
|---|---|---|---|
| `POST` | `/api/register` | `{nickname, password}` | `{userId, nickname, token}` |
| `POST` | `/api/login` | `{nickname, password}` | `{userId, nickname, token}` |
| `POST` | `/api/logout` | — | `{ok:true}`，吊销当前令牌 |
| `GET` | `/api/me` | — | `{id, nickname, courses, updatedAt}` |
| `PUT` | `/api/me/courses` | `{courses}` | `{ok:true, courseCount}` |
| `PUT` | `/api/me/password` | `{oldPassword, newPassword}` | `{ok:true}`，吊销其他令牌 |
| `GET` | `/api/me/groups` | — | `[{code, name, memberCount, isCreator}]` |
| `PUT` | `/api/me/remarks/:userId` | `{remark}` | `{ok:true, remarks}` 私人备注，空串即取消 |
| `DELETE` | `/api/me` | `{password}` | `{ok:true, transferred, disbanded}` 注销账号 |

### 群组

| 方法 | 路径 | 请求体 | 响应 |
|---|---|---|---|
| `GET` | `/api/meta` | — | `{lanUrls:["http://192.168.1.5:3000", …], port}` |
| `POST` | `/api/groups` | `{name?}` | `{code}`，创建者自动入群 |
| `POST` | `/api/groups/:code/join` | — | `{ok:true, pending}`，幂等。pending=true 表示进了审批队列 |
| `GET` | `/api/groups/:code` | — | `{code, name, creatorId, members:[{id, nickname, updatedAt, courses}]}` |
| `DELETE` | `/api/groups/:code/me` | — | `{ok:true}` 退群 |
| `DELETE` | `/api/groups/:code/members/:userId` | — | `{ok:true}` 群主移除成员 |
| `PUT` | `/api/groups/:code/settings` | `{joinMode}` | `{ok:true}` 仅群主 |
| `POST` | `/api/groups/:code/requests/:userId/approve` | — | `{ok:true}` 仅群主 |
| `DELETE` | `/api/groups/:code/requests/:userId` | — | `{ok:true}` 拒绝申请，仅群主 |
| `DELETE` | `/api/groups/:code` | — | `{ok:true}` 解散，仅创建者 |

- `GET /api/groups/:code` 一次返回整群（含各成员课表）。50 人 × ~3 KB ≈ 150 KB，一次拉完最简单。
- **重合课时数由前端基于该响应用 `shared/compare.js` 计算**，服务端不重复实现统计逻辑。
- 邀请码即入群凭证，账号密码即身份凭证，两者职责分离。
- **移除成员**：`store.removeMember(code, ownerId, targetUserId)` 强制三条规则 —— 只有群主能调用（否则 403）、
  群主不能移除自己（400，想退出只能解散）、目标必须还在群里（否则 404）。
  被移除者的 `members` 记录直接删掉，因此 TA 立刻失去 `GET /api/groups/:code` 的权限、
  群组列表里也不再出现；重新用邀请码 join 即可再次入群。前端点击「移除」有二次确认。

## 9. 地点解析与比对规则（`shared/ics.js`、`shared/compare.js`）

### 9.1 parseLocation

| 输入 | area | building | room | 说明 |
|---|---|---|---|---|
| `紫金港东6-328` | 东 | 6 | 328 | 数字楼栋 |
| `紫金港东1A-205` | 东 | 1A | 205 | 字母楼栋 |
| `紫金港化学实验中心-424` | 未知 | 化学实验中心 | 424 | **中文楼栋**（v1 误判点） |
| `紫金港田径场（东）` | 特殊 | 特殊 | — | 类别=田径场，方位=东（括号内） |
| `紫金港田径场（西）` | 特殊 | 特殊 | — | 类别=田径场，方位=西 |
| `紫金港风雨操场（篮排球场）` | 特殊 | 特殊 | — | 类别=风雨操场，方位缺失 |
| `银泉足球场` | 特殊 | 特殊 | — | 类别=足球场，方位缺失 |
| `紫金港机房` | 特殊 | 特殊 | — | 类别=机房 |
| `未知` / 空 | 未知 | 未知 | — | 不参与比对，网格置灰 |

实现：先匹配 `紫金港` 前缀 → 方位 `[东南西北]`（可为空）→ 楼栋 `[\dA-Za-z\u4e00-\u9fa5]+`，
`-` 之后为 room。匹配失败走「特殊场地」分支：类别取白名单
`田径场|足球场|风雨操场|篮球场|排球场|体育馆|机房|操场`，方位从全串扫 `东/南/西/北`（含全角）。

### 9.2 compareLocation

返回 `{level, text}`，`level ∈ {same, nearby, area, cross, unknown}`，优先级 `same > nearby > area > cross > unknown`：

- 任一方 `unknown` → `unknown`（灰）
- 一方特殊、另一方非特殊 → `cross`（红）
- 双方特殊场地依次判定：
  1. 原字符串完全相同 → `same`
  2. 类别不同 → `cross`
  3. 校区前缀不同（紫金港 / 银泉 / 玉泉 / 西溪 / 华家池 / 之江 / 海宁）→ `cross`
  4. 双方都写了方位且不同 → `cross`
  5. 只有一方写了方位 → `nearby`（不敢断言同一片）
  6. 类别是「其他」兜底 → `nearby`
  7. 场地标识不同（剥掉校区/类别/方位/括号后剩下的部分，如「跑道」与「篮排球场」）→ `nearby`
  8. 否则 → `same`
- 双方标准教室：同区域同楼栋同房间 → `same`；同区域同楼栋 → `nearby`；同区域 → `area`；否则 `cross`

> v10 修正：原规则是「类别相同且（方位相同 或 任一方方位缺失）→ same」，属于**宁可信其同**的乐观偏向。
> 典型误报：`紫金港风雨操场跑道`（剑术）与 `紫金港风雨操场（篮排球场）`（排球）会被判成**同教室**（绿），
> 但两者只是同一栋楼里的不同场地。体育课撞课很常见，所以这是一条迟早会触发的假阳性。
> **实测：本次修正不改变当前库里任何一对的比对结果** —— 现有数据里只出现过「同字符串」与
> 「田径场东 ↔ 西」两种特殊场地组合，都不受影响。

### 9.3 单双周处理

数据层不靠奇偶推算，每个槽位自带 `dates`，落在哪一周由真实日期决定。

- **屏幕（单一周）**：按选中周过滤后，同一格通常只剩一个候选。若仍有多个（调休、临时加课），
  分别与对方槽位比对，**取最优等级着色**，格内分行列出各处地点。
- **导出（全学期代表周）**：单周视图与双周视图各算一套数据与等级，背景色取二者最优（§12）。
- **「一致就不管」**：某格单周与双周的（双方课程 + 地点）完全相同时，**不产生任何单双周标注**，
  只显示一份内容。若整份课表单双周完全一致，导出图上不会出现任何周次字样。

### 9.4 重合课时数统计（群组列表用）

对某个成员 X，在**当前选中周**内：

1. 取「我」与 X 在该周内实际发生的槽位，展开成 7×13 的节次占用表。
2. 遍历所有双方同时有课的格子，用 `compareLocation` 得到该格等级。
3. 按等级累加**格子数**（即节数，不是课程门数、不是事件数）。
4. 输出：

```json
{ "same": 6, "nearby": 2, "area": 1, "cross": 5, "unknown": 0, "total": 14 }
```

- 一格有多个候选槽位时，该格的等级已由 §9.3 取最优，只计 1 节，不重复计数。
- 群组列表展示为紧凑彩色徽章，例：`🟢6 🟡2 🔵1 🔴5`，右侧总计 `共 14 节重合`。
- 两人当前周完全无重合 → 显示「本周无重合」，不显示 0 徽章。
- 该统计与比对页共用同一个「选中周」状态，切换周次时同步刷新。

## 11. 组团的呈现

按用户 2026-09-15 决策：**取消「早/午/晚 + 首节次/末节次相同」的判定**，不再划分时段首末。
组团机会由 §10 的**格子配色**与 §9.4 的**重合课时数**直接表达：双方同格即有共同上课时间，
颜色说明彼此教室的远近关系，数字说明重合的量。

## 12. 截图导出

### 12.1 数据来源：全学期代表周（与屏幕解耦）

导出**不克隆屏幕上的表格**，而是新建离屏容器、用独立数据重新渲染一遍。数据口径：

- 教学周 = 从第 1 周（§6 基准）起的连续周。每个格子按**周次奇偶**拆成两套视图：
  - **单周视图**：`dates` 落在奇数教学周的槽位
  - **双周视图**：`dates` 落在偶数教学周的槽位
- **规律性过滤（重要）**：只有整个学期出现 **≥2 次**的槽位才进入导出视图。
  实测其中一份的 39 个槽位里有 **20 个只出现一次**——它们是期末考试条目
  （`20270104` 第 17 周整天的「微积分 / 信息与电子 / 数字音视频」等）与国庆调休补课
  （`20261010` 周六那批），会和常规课撞在同一格，制造大量假差异：
  **不过滤时导出图有 28 处单双周标注，过滤后降到 5 处**（且 ≥2 与 ≥3 结果一致，说明 2 是稳定阈值）。
  该过滤**只作用于导出视图**；屏幕上始终按真实日期原样显示，不丢数据。
- 两套视图分别与对方比对，各自得到等级与地点文本。
- 格子背景 = 两套等级取最优（`same > nearby > area > cross > unknown`）。
- **标注规则**：
  - 两套内容完全一致 → **不标**，只显示一份（「一致就不管他」）
  - 两套不同 → 分行标注 `单周 …` / `双周 …`
  - 只在单周或只在双周有课 → 视作不同，标注实际有课的那套；另一套不写文字（格子本身空着即可，避免图面啰嗦）
- 结果：导出的图与「今天第几周」「屏幕上选了第几周」**完全无关**，同一天导两次结果一致，
  换周次也不会导出差别的图。

### 12.2 标题与文件名

- 标题：`{我} 与 {TA} 组团课表（全学期）`；全图存在任意单双周差异标注时，标题带
  `（全学期 · 单双周）`。
- 文件名：`{名字A}_与_{名字B}_组团课表.png`；存在单双周差异时追加 `_单双周`，
  即 `{名字A}_与_{名字B}_组团课表_单双周.png`。
- 默认 `我` / `TA`，过滤 `[\/\\:*?"<>|]` 为 `_`。
- 昵称提取：注册/上传时从 `.ics` 文件名智能提取（剥离 `Elychron`/`Celechron`、「课表」「课程表」
  等前后缀，长度 1–6 才采纳）用于预填输入框，用户可覆盖。

### 12.3 三条硬性约束（v1 踩过的坑，必须保留）

1. **离屏渲染且必须先定宽**：容器 `position:absolute; left:-9999px`，**在测量之前就要给它一个确定的
   `width`**（实现里是 1080px），然后再按内容宽度修正。
   绝对定位 + `width:auto` 的元素按内容「收缩适应」，而导出表格是 `width:100%`，
   实测会把 `scrollWidth` 撑到 **11266px**，导出一张几乎全空的巨图。
   v1 挂在正常文档流里所以没暴露这个问题——离屏后才能看到。
2. **表头不得 sticky**：导出用的表格模板**不复用**屏幕的 `th { position: sticky }` 规则
   （屏幕上是 `.schedule.sticky-head`，导出只带 `.schedule`），否则 `html2canvas` 会让表头跑到第二行。
3. **单元格不设固定高度**：`td` 只用 `min-height` + `padding` 让内容撑开，防止文字重叠。

> 实测结果：导出容器 1092×1569，`th` 计算样式为 `static`，生成 PNG 约 844 KB，
> 文件名 `小灰_与_阿齐_组团课表_单双周.png`。

## 13. 页面流程

1. **登录页**（未登录时的唯一入口）
   - 昵称 + 密码 + 确认密码 → 注册；或昵称 + 密码 → 登录
   - 令牌写入 `localStorage`，后续自动登录；`401` 时清令牌回本页
   - `localStorage` 全部读写包 `try...catch`（隐私模式不报错），失败时退化为「本次会话内有效」的内存存储
2. **首页**（已登录）
   - 顶部：`你好，小灰` + 我的课表状态（`已上传 37 门 · 更新于 9/15`）/「上传课表」按钮
   - 「创建群组」：输群名（选填）→ `POST /api/groups`
   - 「加入群组」：输 6 位邀请码 → `POST /api/groups/:code/join`
   - 「我的群组」：列表（群名、人数、我是不是创建者），点进群组页
   - 支持 URL 参数 `?code=483920` 直接落到入群确认（二维码扫出来的就是这个）
   - 底部次要入口「本地快速比对（不上传）」：沿用 v1 纯前端双文件逻辑，`file://` 也能用
3. **群组页**
   - 顶部：群名 + 超大 6 位邀请码 + 二维码（点击全屏放大供扫码）+ 复制链接按钮
     （页面跑在 `localhost` 时二维码用 `GET /api/meta` 的局域网地址，否则用 `location.origin`）
   - 周次切换器（与比对页共用状态）
   - **成员列表**：自己标「你」；每人一行显示昵称、课表更新时间、**按等级分类的重合课时徽章**
     （🟢6 🟡2 🔵1 🔴5 · 共 14 节重合）；点任一成员 → 跳到比对页
   - 底部：「上传 / 更新我的课表」「退群」；创建者额外有「解散群组」
4. **比对页**
   - 标题 `我(小灰) ↔ TA(阿齐)` + 周次切换器 + 图例 + 网格 + 导出按钮
   - 导出按钮旁一行小字说明口径差异：`导出全学期（含单双周），与当前周次无关`

## 14. 错误处理

| 场景 | 表现 |
|---|---|
| 未登录 / 令牌过期 | 清 `localStorage` 令牌，跳登录页，提示「登录状态过期了，请重新登录」 |
| 昵称已被占用 | 注册时 `409` → 「这个昵称已经有人在用了，换一个吧」 |
| 昵称或密码错误 | 统一文案「昵称或密码不对」，不区分 |
| 连续失败 5 次 | 「试得太频繁了，等一分钟再试」 |
| 邀请码格式错 | 输入框即时标红，不发请求 |
| 群组不存在 / 已解散 | 提示并回首页 |
| 想退群但是创建者 | 「你是群主，可以直接解散群组」 |
| `.ics` 解析出 0 节课 | 「没解析出课程，确认是 Elychron/教务导出的 .ics 吗」，不写入 |
| `.ics` 里全是「未知」地点 | 允许上传，网格整体置灰并提示 |
| 网络失败 | 顶部 toast「连接不上服务器，检查是否还在同一 WiFi」 |
| 服务端 5xx | `{error}` 文案原样展示 |

## 16. 微信小程序迁移约束

- `shared/ics.js` / `periods.js` / `weeks.js` / `compare.js` 内**禁止出现 `document`、`window`、`localStorage`**，
  全部为纯函数，可直接复制进小程序 `.js`。
- 网络层：前端统一走 `public/api.js` 的 `api(path, method, body)`，迁移时只替换该函数为 `wx.request`，
  令牌改从 `wx.getStorageSync` 取。
- 渲染层：HTML `table` 后续改写为小程序 `view` + Flex 网格，故配色一律用 class 名
  （`bg-same` / `bg-nearby` / …），不写内联样式，便于整体搬样式表。
- 全局账号模型天然适配小程序：日后接入微信登录时，只需把「昵称 + 密码」换成 `openid` 绑定，
  `userId` 与课表、群组数据无需迁移。

## 17. 未决与风险

- **HTTP 明文传输密码**：局域网内抓包可见。当前为局域网自用定位的显式取舍；
  若要收紧，可后续加自签 HTTPS 或改为挑战-应答。**这是本设计最大的安全短板，已在文档中明示。**
- **三份 `.ics` 含真实姓名**，已在 `.gitignore` 里用 `*.ics` 通配符排除（不要改成逐个写文件名，
  否则换个名字导出一份就会漏进去）。代码、测试、文档里一律用化名。
- 邀请码为 6 位数字，局域网内可被猜到，但入群后仍需账号身份才能做写操作。
- 局域网访问需放行 Windows 防火墙（首次运行 `node server.js` 时系统会弹窗，选「允许」）；
  文档将附排查说明。
- 若同学手机连的是流量而非同一 WiFi，将无法访问——错误处理中已给出提示文案。
- 群组创建者解散群组会直接删除群组文件，不设二次确认以外的恢复机制（无回收站）。
