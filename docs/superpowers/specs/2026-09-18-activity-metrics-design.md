# 活跃度追踪与后台统计 —— 设计

> 一句话：**服务端按天攒一个统计桶（谁来过、来了几次、做了哪些关键动作），滚动保留 90 天；
> 管理员在独立的「统计」页看活跃 / 新增 / 留存 / 动作 / 用户计量 —— 零依赖，折线自己画。**

## 1. 现在有什么、缺什么

已有的「统计」全是**当下快照**，都在 `/api/admin/overview` 里现算：

| 已有 | 位置 |
|---|---|
| 每人：注册时间/IP、`lastLoginAt`、`lastLoginIp`、`loginCount`、课表数、`idleDays`、dormant/admin/suspect | `store.listAdminUsers()` |
| 汇总 7 个数字：用户数、管理员数、超管数、群数、可疑数、待清理数、传过课表的人数 | `server.js` overview 路由 |
| 审计日志：最近 200 条事件（进程内，不落历史） | `store.readAudit()` |
| `sessions.json` 里每会话的 `lastSeen` | 只在会话有效期内有意义，90 天就删 |

**缺的是时间维度**：没有「按天的活跃 / 新增 / 留存」，所以下面这些问题现在一个都答不了：

- 今天有多少人来过？这周比上周多还是少？
- 上周注册的那批人，现在还有几个在用？
- 大家实际在做什么动作 —— 主要是传课表，还是主要在建群拉人？
- 谁是真活跃用户（活跃天数多），谁只是注册完就再没出现？

## 2. 决定（这一节回答三个口径问题）

### 2.1 三种口径**都要**，因为它们回答不同的问题

| 口径 | 记什么 | 回答的问题 | 实现代价 |
|---|---|---|---|
| **请求级** | 任何**通过令牌鉴权**的请求 | 「今天真的打开用了」 | 一个挂点（鉴权函数），零额外 IO |
| **登录级** | `POST /api/login` 成功 | 「换过设备 / 重新登录」 | 一处 |
| **动作级** | 8 个关键动作（§3） | 「在用哪个功能」 | 八处，都是既有的成功分支 |

三种都记**不重复计数**：同一枚请求只经过一次鉴权函数；登录与动作各自独立成字段，
不会互相污染（请求数里包含登录，但 `logins` 是它自己的计数）。

### 2.2 按天一个文件、滚动 90 天、桶里带账号 id

- 保留 90 天：足够算 30 日活跃与 7 日留存，也不会把磁盘当仓库用。
- 桶里存**去重后的账号 id**（不是只存人数）：只存人数就永远算不出留存、复访、
  「谁在回访」——而那正是这次要看的东西。

### 2.3 单独一个「统计」页（不是塞进管理页）

管理页现在的定位是**操作台**（筛选账号、删号、解散群、看审计）。统计是**观察**，
两者的使用节奏不一样：操作台是「来处理一件事的」，统计页是「来盘一下现状的」。
塞在同一个屏里，统计卡片会把筛选和列表推到折叠线以下。

入口放在管理页顶部，进去是卡片式的一屏，顶部可切 7 / 30 / 90 天。

## 3. 记什么（口径定义）

| 层级 | 触发点（成功之后才记） | 字段 |
|---|---|---|
| 请求 | 任何带有效令牌的 `/api/*` 请求 —— 挂在**共用的鉴权函数**上，一次请求只经过一次 | `users[uid].req++`、`requests++`、`lastAt` |
| 登录 | `POST /api/login` | `logins++`、`users[uid].logins++` |
| 注册 | `POST /api/register` | 当天 `newUsers` 加一个 id |
| 动作 | 见下表 | `users[uid].acts[key]++` |

动作白名单（**固定集合**，不是任意字符串 —— 免得统计表被写成第二份审计日志）：

| key | 触发点 |
|---|---|
| `course_upload` | `PUT /api/me/courses` 成功 |
| `group_create` | `POST /api/groups` 成功 |
| `group_join` | `POST /api/groups/:code/join` 成功且**真的进了群**（审批模式下只是登记申请，不算加入） |
| `group_leave` | `DELETE /api/groups/:code/me` 成功 |
| `group_transfer` | 群主转让成功 |
| `invite_create` | 生成邀请链接成功 |
| `password_change` | 改密码成功 |
| `account_delete` | 注销成功（**在删号之前记**，否则 id 已经没了） |
| `admin_action` | 管理动作（授/撤管理员、重置密码、删号、解散群）合成一类 |

**纯前端动作不记。** 「打开比对页」「切周次」这类发生在浏览器里（比对是
`shared/compare.js` 在前端算的，服务端没有对应请求），要记就得新开一个上报接口 ——
那是一条**可被脚本刷的写接口**，收益只是「多一个看过的计数」。这次不做，
留作以后的扩展点（真要做，就加 `POST /api/me/beacon` + 事件名白名单 + 限流）。

## 4. 存什么

### 4.1 一天一个文件

```
data/stats/2026-09-18.json
```

```json
{
  "v": 1,
  "day": "2026-09-18",
  "requests": 412,
  "logins": 17,
  "newUsers": ["u_a1b2c3d4"],
  "users": {
    "u_a1b2c3d4": {
      "req": 40,
      "logins": 2,
      "lastAt": 1789712345678,
      "acts": { "course_upload": 1, "group_create": 1 }
    }
  }
}
```

- **活跃人数 = `Object.keys(users).length`** —— 去重是结构自带的，不用额外算。
- `acts` 里只写计数 > 0 的动作（省空间，也省得看一堆 0）。
- `newUsers` 存 **id 列表**而不是数字：账号注销之后用户表里就查不到了，
  但「那天新增了几个」是历史事实，不该因为后来注销而变；留存也要按 id 求交集。
- 时间戳只留每人的 `lastAt`（最近一次动作），够回答「他今天最后什么时候在」。

### 4.2 为什么一天一个文件，而不是一个大文件

`writeJsonAtomic` 只能整文件重写。90 天合在一个文件里的话，**每次落盘都要重写全部历史**：
按每天几百人算，那是一个 MB 级的文件、每 10 秒写一次 —— 而其中 99% 的内容一个字都没变。

按天分文件之后：

| | 一个合并文件 | 一天一个文件（本设计） |
|---|---|---|
| 每次落盘的写入量 | 全部 90 天 | 只有今天（几十 KB 封顶） |
| 修剪 | 读出来、删字段、写回去 | `unlink` 一个文件 |
| 单文件损坏的影响 | 全部历史 | 那一天 |

### 4.3 加密范围：**明文**，理由写在这里

存储加密（`2026-09-17-storage-encryption-design.md`）加密的是**内容**：
昵称、课表、私密备注、对外备注。它明确把**时间戳与 `userId` 关联**留在明文
（那张表里就写着「保持明文：时间戳、群成员 `userId` 列表」；`sessions.json` 更是
`userId + lastSeen` 全明文）。

统计桶里只有「哪个账号 id 在哪天来过、几次、做了哪类动作」：

- **没有**任何姓名 / 课表 / 备注内容；
- id 是随机句柄，把它和人对上号需要 `users.json`（昵称在那里是密文）；
- 「某些 id 在某天活跃」这层关联，`sessions.json` 今天已经在明文中提供了。

所以**沿用明文**，不加新的加密用途（KIND）。真要收紧，正确做法是给
`users` 那一段加一个 KIND 整段封起来 —— 但 id 作为 key 仍会留在明文里，
收益有限。这条判断写在这里，免得下次有人以为是漏了。

### 4.4 保留与修剪

- `STATS_KEEP_DAYS = 90`。读的时候忽略更老的；每天清理时 `unlink` 掉更老的文件。
- 修剪挂在**已有的每日清理**里（`store.cleanup()`，服务启动时会跑一次、之后每 24 小时一次），
  不新开定时器。

## 5. 写放大：绝不在请求路径上写盘

照抄会话表已经验证过的那套（`LASTSEEN_WRITE_MS` 节流）：

| 环节 | 做法 |
|---|---|
| 记账 | `touch()` 只改**内存里今天那个桶** + 标脏。同步、零 IO、不 await |
| 落盘 | `STATS_FLUSH_MS = 10_000`（对齐 sessions 的 10 秒）定时写；**脏了才写** |
| 关服 | `server.on('close')` 里 `flushStats('关服')` —— 和 `flushSessions` 同一个位置 |
| 跨天 | 内存桶带 `day`；下次记账时比较本地日期，不同就先把旧桶落盘、再开新桶 |
| 并发 | `withLock('stats')` + `writeJsonAtomic`（和其它文件同一套原子写） |
| **写之前先并一次盘** | **任何一次写、任何一次读之前，先把盘上那份并进内存**。否则会丢数据：当天已经落过盘、进程重启（或过了零点）之后内存里为这天新建一个空桶，下一次落盘就把当天的历史计数覆盖掉 —— 和 `store.js` 里 `invitesOf` 那个坑是同一类（写实现时先写了这条用例，它当场就红了） |
| 崩溃损失 | 最多丢 10 秒的计数 —— 和 `lastSeen` 一样，明确接受 |

**单进程假设**：并盘用的是「相加」，所以两个进程同时写同一天会重复计数。
这个应用本来就是单进程（`withLock` 也是进程内的），写在这里只是别让它变成默认可以踩的坑。

**实现位置**：桶的读写独立成 `shared/stats-store.js`（依赖由外面注入：目录 / readJson /
writeJsonAtomic / withLock / 时钟）。`store.js` 已经两千行，而桶的规则自成一套，
分开更好读，也能直接拿一个临时目录测。口径仍然只有一份，在 `shared/stats.js`。

**「天」的边界用服务端本地时区**（`YYYY-MM-DD` 本地日）。前端管理页的日期筛选
（`dayStart`）也是本地日，两边口径一致。部署时锁一个时区（`TZ=Asia/Shanghai`），
否则统计会跟着机器漂 —— 这一条写进 `docs/DEPLOY.md`。

## 6. 读：`GET /api/admin/stats?days=30`

- `requireAdmin`；`days` 只接受 **7 / 30 / 90**（白名单，和邀请有效期一个套路），
  其它值 400（不静默回落 —— 猜错口径比报错更难查）。
- 聚合**在服务端算好**再返回：前端只画图、只渲染数字，不重复实现口径
  （和 `suspects` / `dormant` 都在服务端算是同一个原则）。

```json
{
  "days": 30,
  "series": [
    { "day": "2026-08-20", "active": 12, "newUsers": 2, "logins": 20, "requests": 340,
      "acts": { "course_upload": 5, "group_create": 1 } }
  ],
  "summary": {
    "today":  { "active": 9, "newUsers": 1, "logins": 14, "requests": 210 },
    "range":  { "activeUnique": 23, "newUsers": 12, "logins": 190, "requests": 4100,
                "avgRequestsPerActive": 17.8, "days": "2026-08-20 ~ 2026-09-18" },
    "retention7": { "cohort": 10, "returned": 4, "rate": 0.4 },
    "actions": { "course_upload": 120, "group_join": 31 },
    "avgCourses": 18.3, "courseUploaded": 14
  },
  "top": [
    { "id": "u_...", "nickname": "小灰", "activeDays": 26, "requests": 431, "lastAt": 1789... }
  ]
}
```

口径必须写在界面上，别让人猜：

- `range.activeUnique`：区间内**所有桶的 id 并集**（跨天去重）—— 不是每天人数相加。
- `retention7`：**经典 7 日留存** = 7 天前那一天新增的人里，今天仍然活跃的比例。
  （分母 = `series[day-7].newUsers`，分子 = 该集合 ∩ 今天的活跃集合。）
  选这个口径是因为它一句话能说清；界面上直接写这句，不写「留存率」三个字就完事。
- `top`：按 `activeDays` → `requests` → `lastAt` 排序取前 10；昵称从 `users.json` 取
  （服务端解密，管理员本来就在管理页看得到昵称）。
- 没有任何桶时：`series: []`、`summary` 全 0、`top: []`，UI 显示
  「还没有统计数据 —— 从这一版上线那天开始记」。

## 7. 界面

- **入口**：管理页顶部一颗 `#btn-admin-stats`（`link-btn`），只在管理员可见的管理页里，
  本来就已经是管理员专属；点进 `show('stats', { title: '统计', back: 回管理页 })`。
- **时间窗**：`#stats-range`，复用 `.segmented`（`data-days="7|30|90"`），默认 30。
- 卡片：
  1. **活跃** —— 今日 / 7 日 / 30 日活跃 + 7 日留存 + 活跃人数折线（按当前窗口）
  2. **增长** —— 今日 / 区间新增 + 新增折线
  3. **动作** —— 区间内各动作计数（表）+ 人均请求 / 人均课表 / 传过课表的人数
  4. **用户计量** —— 最活跃 10 人（昵称 / 活跃天数 / 请求数 / 最后活跃）
- **折线自己画**：零依赖，`shared/stats.js` 里的纯函数 `sparkPath(values, w, h)` 返回
  一条 SVG `d` 字符串，前端拼 `<svg class="spark">`。全 0、只有一个点、数据缺失
  都要有确定的退化画法（画一条基线，而不是抛异常或画成 NaN）。

`shared/stats.js` 同时被**服务端 require**（算聚合）和**浏览器加载**（画线），
所以：

- 它必须是纯函数、不碰 fs / 网络 / 全局状态；
- 要加进 `server.js` 的 `SHARED_PUBLIC` 白名单（`config/periods/ics/weeks/compare` 之后
  再加一个 `stats.js`）—— 那份白名单的意义是「允许浏览器取的共享模块只有这几个」，
  新增共享模块必须显式登记，否则前端 404。

## 8. 明确**不**记的东西（隐私边界）

写下来是为了以后不被顺手扩展：

- 不记 IP、User-Agent、请求路径、响应耗时、地理信息；
- 不记任何业务内容（课表内容、群名、备注、备注对象）；
- 不记「谁看了谁的比对」—— 那会变成关系图谱，超出「活跃度」该有的范围；
- 只有管理员能读（`requireAdmin`）；普通用户看不到任何人的统计数字，
  包括自己的（这个页面不是给用户看的）。

## 9. 失败隔离：统计永远不能影响业务

| 情况 | 行为 |
|---|---|
| 记账本身抛错 | `touch()` 内部 try/catch + `console.warn`，请求照常返回（和 `appendAudit` 一样的 fire-and-forget 精神） |
| 落盘失败 | 保留脏标记、下次再写（sessions 的做法），错误只进日志 |
| 某个桶文件损坏 | `readJson(file, () => null)` 兜底，当那天空；**绝不让统计把管理页搞挂** |
| 统计目录不存在 | `init()` 里建；不影响任何老流程 |

## 10. 老数据与迁移

- **不回填历史**：过去没记过，补不出来。不假装有数据 —— 上线第一天就是第一条数据。
- 头 7 天留存、折线都会稀疏，UI 必须优雅处理（「数据还不够」而不是画一条从 0 开始的假线）。
- 本改动**不动任何既有文件**：只新增 `data/stats/`。所以它和
  「群码不再当门票」那批（会写全部群文件）可以分开上线、也可以一起上。
- `docs/DEPLOY.md` 要加两行：统计目录的位置与保留策略；`TZ` 要锁死（§5）。

## 11. 测试

**`test/stats.test.js`（新，纯函数）**

| 用例 | 断言 |
|---|---|
| `dayKey` | 本地日；跨零点换 key；给定时区下不漂 |
| `summarize` 去重 | 同一个人在多天出现 → `activeUnique` 只算一次 |
| `summarize` 留存 | 构造 7 天前的 cohort 与今天的活跃集合，rate 与手算一致；cohort 为 0 时 rate 为 0 而不是 NaN |
| `summarize` 空数据 | 没有桶 → 全 0、`series: []`，不抛 |
| `sparkPath` | 全 0 / 单点 / 两点 / 有 null 都能给出确定路径，不产生 NaN |

**`test/store.test.js`（或新文件）**

| 用例 | 断言 |
|---|---|
| 请求去重 | 同一天同一账号 `touch` 五次 → 活跃人数仍是 1，`req` 是 5 |
| 跨天分桶 | 改本地日 → 旧桶落盘、新桶另开，两个文件各一份 |
| 落盘节流 | 连续 `touch` 不立刻写盘；`flushStats()` 之后文件里有数 |
| 修剪 | 造一个 91 天前的桶 → 清理后文件没了，90 天内的还在 |
| 记账失败不影响调用方 | 注入一个会抛的写入 → `touch()` 不抛、请求路径不受影响 |

5. 前端：统计页 + 折线 + 管理页入口

7. 全量测试跑绿
8. 部署：第一次启动建目录；从那天开始记，**不回填**
