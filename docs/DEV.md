## 几个设计上的取舍

- **单双周不做奇偶推算**，直接按 `.ics` 里的真实日期判断。调休、临时加课、停课都天然正确。
- **屏幕按周显示，导出是全学期**。导出的图包含单周/双周两套，只有真正有差异的格子才标注
  「单周 / 双周」；两套一致的课不产生任何标注。导出与当前选中的周次无关。
- **导出会剔除只出现一次的条目**。教务导出的 `.ics` 里混着期末考试和调休补课，它们只出现一次
  却会和常规课撞格。实测：不过滤时导出图有 28 处假标注，过滤后剩 5 处真单双周。
  该过滤**只作用于导出**，屏幕上仍按真实日期原样显示。
- **管理页的筛选排序全在浏览器里算**，`/api/admin/overview` 没有查询参数。
  它本来就把全部账号（连同注册时间、登录次数、没露面天数那些字段）一次性发过来了，
  加查询参数只会给每次输入添一个来回。等账号真上千条再谈。
  两个坑记在这里：**注册时间区间必须按本地日解析**（`new Date('2026-09-15')` 是 UTC 午夜，
  东八区会把当天 00:00–08:00 注册的账号漏掉），**数字框留空是「不限」而不是 0**。
- **「成员能不能分享邀请码」（`memberShare`）现在是真的边界。** 它让群主成为唯一的码源
  （谁被放进来、什么时候放的，群主心里有数）。**上一版它不是**：那时群码既是寻址用的 id，
  又是一张不可收回的永久邀请码，所以它必然出现在成员看得到的响应里，开关只能算行政手段。
  现在群码退回成「群的地址」、入群只认邀请链接（见下一条），成员从接口里也拿不到任何能用的码。
  这块的历史（v8 删掉 `memberCanInvite`：不能后端不校验的假开关）记在
  [成员分享开关的设计](superpowers/specs/2026-09-18-member-share-toggle-design.md)，
  拆开的那一刀记在
  [群码不再当门票的设计](superpowers/specs/2026-09-18-group-code-not-a-ticket-design.md) ——
  动这块之前先读那两份。管住入口的硬办法仍然只有两条：把「谁能进群」切成「要我同意」，和移除成员。

## 群码是地址，票才是凭证

一句话：`g.code`（8 位）只用来**寻址** —— 它是文件名，也是所有 `/api/groups/:code/*` 的路径参数；
**入群只认 `invites[]` 里的票**，拿群码去 `/join` 一律 404。

为什么值得拆开：群码不可收回、不可过期，而且必然出现在每个成员都拿得到的响应里（前端要拿它调接口）。
它一旦同时是票，就等于给每个群挂了一张收不回的永久门票 —— 想收回只能换群码，而换群码会改掉群的地址。
拆开之后，「成员分享」开关才第一次成为真边界（见上一条）。

配套的几条，都在 `shared/store.js` 里：

- **每个群自带一条永久链接**（`label: '默认链接'`）：建群时就有，老群由 `init()` 一次性补齐。
  有它，「成员能不能分享」才有个东西可分享；没有它，成员打开群组页只能看到一张空卡片。
  判据是 **`invitesSeeded`** 而不是「票是不是空的」—— 群主故意把票收光之后，
  界面该显示「群主似乎没有分享他的群群~」，而不是下次启动时被我们偷偷补回去。
- **票码全仓库唯一**（`usedCodes()`）：票是唯一的入口，跨群重码会**静默进错群**，
  所以生成时扫一遍所有群文件（含作废/过期的历史票码 —— 复活旧码等于让拿到旧链接的人重新获得入口）。
- **「换群码」已经删掉**：群码不再是凭证之后，它什么也收不回来、却会改掉群的地址
  （前端手上那个 `code` 立刻全部 404）。`resolveGroupFile()` 里对 `codeRotatedFrom*` 的兼容读
  **保留** —— 老数据里确实有换过码的群，删了就读不回来。所以 `data/groups/` 下的
  文件名不一定等于群码，排查时以文件里的 `code` 字段为准。
- **`init()` 会写盘**（补默认票 + 打 `invitesSeeded` 标记）：它是幂等的，但意味着
  「起服务 / 跑 CLI / 写个脚本看一眼」都会触发这次迁移。别拿 `init()` 当只读工具用。
- 上线迁移的完整交代（旧群码链接为何全部失效、6 位老码为什么不再需要淘汰、
  回滚会发生什么、为什么故意不给旧前端兜底 `ownerCode`）见
  [群码不再当门票的设计](superpowers/specs/2026-09-18-group-code-not-a-ticket-design.md) §9。

## 活跃度统计（实现备注）

三种口径同时记，各自回答不同的问题：**请求级**（任何带令牌的请求 → 今天真的来过）、
**登录级**（换设备 / 重新登录）、**动作级**（9 个白名单动作 → 在用哪个功能）。
请求级挂在 `requireUser()` 上 —— 它是所有带令牌请求的唯一必经之路，一次请求只经过一次，
所以既不会漏也不会重复计。

存的是**一天一个文件**（`data/stats/YYYY-MM-DD.json`）：

```json
{ "day": "2026-09-18", "requests": 412, "logins": 17, "newUsers": ["u_..."],
  "users": { "u_...": { "req": 40, "logins": 2, "lastAt": 1789..., "acts": { "course_upload": 1 } } } }
```

活跃人数就是 `users` 的键数（去重是结构自带的），留存靠跨天求 id 交集。

几条硬约束，都是踩过或差点踩到的：

- **请求路径上绝不写盘**：`touch()` 只改内存里当天的桶，10 秒落一次
  （和会话的 `lastSeen` 同一个套路），关服前再冲一次。崩溃最多丢 10 秒的计数，明确接受。
- **写之前先把盘上那份并进内存**：当天已经落过盘、进程重启（或过了零点）之后又来了新账，
  直接拿内存里的空桶写盘会把当天的历史计数**无声覆盖**（这条用例先红过一次）。
  `shared/stats-store.js` 里的 `loaded` 表就是干这个的，动它之前先读那段注释。
- **读数优先用内存那份**：管理员刚刷完页面就能看到 10 秒内的活跃，不用等落盘。
- **口径只有一份**：`shared/stats.js` 既被服务端 require（算聚合），又被浏览器加载（画折线）。
  所以它必须是纯函数；新加共享模块记得登记进 `server.js` 的 `SHARED_PUBLIC`，否则前端 404。
- **只记「谁在哪天来过、来了几次、做了什么类别的动作」**：不记 IP、UA、请求路径、耗时，
  也不记任何业务内容。管理员能看，普通用户看不到任何人的数字（连自己的都不给）。
- **不回填历史**：过去没记过，补不出来 —— 上线第一天就是第一条数据，界面会说「还没有数据」。
- 「天」的边界用**服务端本地时区**，所以部署时要锁 `TZ`（见 DEPLOY.md），否则数字会跟着机器漂。

## 给开发者：接口一览

服务端是 `server.js` 里一张路由表，鉴权走 `Authorization: Bearer <token>`。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/meta` | 健康探针 + 页脚版本号：`{ ok, app, tagline, version, build }`。唯一免鉴权接口，Docker 健康检查也打它 |
| GET | `/api/captcha` | 注册验证码：`{ enabled, id, image }`，`image` 是一张 PNG 的 data URL |
| POST | `/api/register` `/api/login` `/api/logout` | 账号（注册要带上 `captchaId` + `captchaAnswer`） |
| GET / DELETE | `/api/me` | 当前账号 / 注销 |
| PUT | `/api/me/courses` `/api/me/password` | 上传课表 / 改密码 |
| PUT | `/api/me/remarks/:targetId` | 个人备注（只有自己可见） |
| GET | `/api/me/groups` | 我加入的群 |
| POST | `/api/groups` | 建群 |
| POST | `/api/groups/:code/join` | 入群（或提交申请）。**这里的 `:code` 是邀请码，不是群码**（群码已经不能入群了） |
| GET | `/api/groups/:code` | 群详情（含重合统计与可用的邀请票；群主看全部，成员只看还能用的） |
| PUT | `/api/groups/:code/settings` | 群设置（改名 / 入群策略 / 能不能让成员转发邀请码） |
| POST | `/api/groups/:code/transfer` | 转让群主（**要密码**，复用改密码那条限流桶） |
| POST / DELETE | `/api/groups/:code/invites…` | 邀请链接：新建 / 作废 / 删除存档 |
| POST / DELETE | `/api/groups/:code/requests/:userId` | 审批进群申请 |
| DELETE | `/api/groups/:code/members/:userId` | 移除成员 |
| GET | `/api/admin/overview` | 管理员视图：账号 / 群组 / 审计 |
| GET | `/api/admin/stats` | 活跃度统计（`?days=7/30/90`，白名单）：按天的活跃 / 新增 / 登录 / 动作 + 留存 + 用户计量 |
| PUT / DELETE / POST | `/api/admin/users/:id…` | 授权、删除账号、重置密码 |
| DELETE | `/api/admin/groups/:code` | 解散任意群组（「换群码」那条已随功能一起删掉） |

授权管理员走命令行（因为这是**本机操作**——能敲这条命令就说明你本来就摸得到 `data/`）：

```bash
node server.js --make-admin 你的昵称     # 设为管理员
node server.js --revoke-admin 你的昵称   # 取消管理员
```

先在网页上把账号注册出来，再执行这条命令。

迁移幂等与回滚、四种"拒绝启动"）、会话令牌哈希化（含老数据升级不踢人下线）、
超管守卫（撤不掉/删不掉/重置不了）、真实来源 IP（反代后分桶 + 伪造头必须无视）、
页脚版本号（版本只认 package.json，提交号在假仓库里验松散 ref / packed-refs / 分离头指针）。

> 写测试的人注意：**改密码那条路要塞三次 scrypt**（验旧密码 → 算新哈希 → 拿新密码登回来），
> 几百毫秒起步，机器一忙就超。别用固定 `setTimeout` 等它 ——
> 用 `test/screens.test.js` 里那个 `until()` 轮询到令牌真的换了再断言。
> 「等一下再看」在这条路上是间歇性红的来源。
> 同理，管理页那两张列表也别死等 `tick(600)`（并行跑整套时 CPU 一挤就不够，
> 两条筛选用例因此偶发红过）—— `openAdminAt()` 现在先等到列表真的画出来。

> 如果 `npm test` 报「找不到测试文件」（旧版 Node 不会展开 `--test` 里的通配符），
> 直接写全：`node --test test/*.test.js`。

> 仓库根目录的三份 `.ics` 是真实课表（含真实姓名），已被 `.gitignore` 的 `*.ics` 通配符排除。
> 缺少它们时，依赖真实数据的少数测试会自动跳过。
> 测试按目录扫描这些文件、靠内容认它们，**文件名不会出现在代码里**——
> 所以你换成什么名字重新导出都不影响。

## 版本管理与推送

**只推送 `main` 分支。**

```
main            要推送的分支，干净的起点（单个初始提交）
local-archive   早期开发历史，仅本地保留，永不推送
```

为什么这么分：仓库根目录那几份真实课表虽然已经被 `.gitignore` 挡在库外，但**早期提交里
还留着同学的真名**（当时的测试夹具和文档）。与其重写历史（会改掉全部提交哈希），
不如从当前这份已经全部化名的状态重新起一个根提交，只把这个提交推上去。

⚠️ **不要用 `git push --all`，也不要用 GUI 里的「推送所有分支」**——那会把
`local-archive` 连它背后的 44 个提交一起推上去，化名就白改了。

```bash
git remote add origin <你的仓库地址>
git push -u origin main
```

之后正常 `git add` / `git commit` / `git push` 就行，历史会从 `main` 这个根提交往后长。

## 后续规划

方向、坑和优先级写在 **[docs/ROADMAP.md](docs/ROADMAP.md)** 里，那里每一条都标了
「现在是什么样」，免得误以为已经做过了。摘要（按优先级）：

1. **备份 + 写前快照**——成本最低，救的是最不可逆的损失
2. **限流改成按真实 IP / 按账号双轨**（真实 IP 已支持，见 [关于真实 IP](#关于真实-ip)；
   「按账号」那一轨还没做）
3. **超时与抗打加固**（`headersTimeout` / `requestTimeout` / 单 IP 并发上限）
4. **审计聚合与自动封禁**——在有人开始攻击之后再补就晚了
5. **接入学校身份认证**——收益大但外部依赖重，可以晚
6. **课表匹配（找相似课表的人）**——功能上最有意思，风险上也最重，放最后且单独评审

> ~~传输加密~~ **已完成**：正式服由反向代理提供 HTTPS，容器只监听本机环回。

> 第 6 项要注意：现在的可见范围是「同群成员」，本质上是熟人网络。
> **一旦开放陌生人匹配，就从「熟人可见」变成「陌生人可见」**，
> 而课表里含真实姓名、每周行踪、常去的楼栋教室。这条上线前应当单独做一次评审。
